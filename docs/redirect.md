# HTTP 换源与 HTTPS 透传

默认关闭。开启后容器同时监听下载 HTTP `:80` 和 TLS `:443`。DNS 只在两个监听都正常时将匹配的源域名指向容器；关闭或监听失效后恢复 CDN 优选或上游解析。

## HTTP 请求

1. 按平台开关和规则确定目标域名。停用或隐藏的平台不会被全局规则重新接管。
2. 开启智能兜底时，使用目标节点探测完整请求 URI，包括转义路径和查询参数，只请求 `bytes=0-1`。
3. 目标资源可用时返回 302，让 Xbox 直接从目标 CDN 下载。
4. 目标返回 404/410，或探测超时、403、5xx 时，本次请求通过原 CDN 回源代理。超时、403、5xx 属于未知结果，不缓存为资源缺失。

明确的存在或缺失结论按完整 URI、目标节点和规则版本缓存五分钟，容量上限为 4096；同时发起的相同探测会合并，某个分块缺失不会污染同目录的其他分块。

回源保留原始 Host、路径、查询参数和 Range。此时下载数据经过 NAS。因为源域名的 DNS 已指向容器，302 回到源域名会形成循环，所以使用回源代理。

## HTTPS 请求

容器从 ClientHello 读取 SNI，仅允许启用的源域名，并将原始 TLS 握手和后续字节发送到原 CDN。Xbox 仍验证真实 CDN 证书，容器不解密下载内容，也不会把 HTTPS 请求强制改成 `.cn`。

回源优先使用手动锁定 IP 或有效的自动优选节点；没有节点时通过独立上游 DNS 解析，避免再次解析到容器自身。HTTPS 透传和 HTTP 回源都经过 NAS，速度会受 NAS 网卡和出口路径影响。

透传支持带明文 SNI 的 TCP/TLS 请求；没有实现 QUIC/HTTP3 转发或加密 SNI 的目标路由。DNS 优选与换源均不能保证提升每条网络线路的下载速度。

## 配置与开关

```yaml
listen:
  http: ":80"
redirect:
  enabled: false
  tls_addr: ":443"
  smart_fallback: true
```

管理界面的 HTTPS 默认使用 `:8443`。如果旧配置已占用 `:443`，先改管理端口并重启，再开启换源。

开关变更立即生效；监听端口和证书变更会提示重启。启动监听失败时配置会回滚，DNS 不会接管到故障代理。同一对域名只能启用一个方向，配置中的循环会被拒绝。

建议先使用 DNS 优选并实机比较下载速度，再按需启用换源。NAS 与 Xbox 的出口、代理和分流策略应保持一致。
