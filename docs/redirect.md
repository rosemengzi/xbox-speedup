# 302 重写层与智能兜底

默认关闭。开启后容器才占用 80 端口。它是纯 DNS 加速之外的**可选增强**。

## 什么时候有用

游戏机被分配到哪个下载域名，取决于它出口 IP 的地理判定：

- 国内裸连 → 游戏机直接请求 `.cn` 域名 → 纯 DNS 把 `.cn` 解析到最快国内 CDN 即满速，**用不到 302**。
- 挂了加速器/被误判 → 游戏机请求 `.com` 域名 → 纯 DNS 只能解析到最快 Akamai IP（`.com` 域名不能用 `.cn` 的 CDN IP，CDN 按 Host 头取资源）。这时把 `.com` 302 改写成 `.cn`、连 Host 一起换，可强制走国内 CDN，对冷门老游戏更稳。

## 工作机制

```
DNS 对「重写源域名」返回容器 IP ──► 游戏机连容器 :80 ──► 读 Host+路径 ──► 302 跳到目标域名
目标域名 DNS 解析到真实最快 IP ──► 游戏机直连目标 CDN 下载（容器不碰流量）
```

规则是一张可开关的双向表（见配置 `redirect.rules`）：`.com→.cn` 和 `.cn→.com` 都能配。
平台内置重写（如战网区域域名→`blzddist1-a.akamaihd.net`）也并入这张表。

## 智能兜底（smart_fallback）

解决「有些游戏 cn 没有」的问题。`.cn` 由世纪互联运营，目录是全球目录的子集，
不在国区渠道的游戏，cn 源站没有该下载块，回源直接 404/403 → 下载卡死。

开启后，命中重写规则时先对目标域名的最快 IP 发一个 `Range: bytes=0-1` 探测：

- 目标有该资源（200/206）→ 正常 302 到目标域名（轻量，不碰流量）。
- 目标缺该资源（404/403/410）→ **就地反向代理回源域名**，把内容取回来转给游戏机，避免下载失败。

探测结论按 ContentID 目录粒度缓存，同一游戏只探一次，后续分块请求零额外开销。

### 为什么缺资源时要「反向代理」而不是再 302

DNS 已经把重写源域名劫持到容器 IP。如果此时再 302 回源域名，游戏机会重新解析它、
又拿到容器 IP，形成**死循环**。所以「保留原域名」这一支只能由容器就地反代回源域名自己池里的
最快 IP（Host 保持原样）。这是唯一会让容器承载下载流量的分支，且仅在「目标缺资源」的罕见情况触发。
