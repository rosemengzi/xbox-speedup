# 详细使用说明

本文面向已经启动容器的用户。首次安装先看 [威联通部署指南](deploy-qnap.md) 或 [群晖部署指南](deploy-synology.md)；功能总览见 [README](../README.md)，模块实现见 [架构说明](../DETAILS.md)。

## 1. 登录与第一次使用

从与 Xbox 同一局域网的电脑或手机打开：

```text
http://<容器IP>:8080
```

管理用户名固定为 `admin`。密码按以下顺序读取：

1. `.env` 中设置的 `XBOX_WEB_TOKEN`。
2. 未设置时，数据目录中的 `web-token`；没有该文件则首次生成。

例如部署时使用 `XBOX_DATA_DIR=/volume1/docker/xbox-speedup-data`，在 NAS SSH 中查看自动生成的密码：

```bash
sudo cat /volume1/docker/xbox-speedup-data/web-token
```

威联通按其部署指南的示例目录则执行 `sudo cat /share/Container/xbox-speedup-data/web-token`。实际使用其他目录时，替换为自己挂载到容器 `/data` 的宿主机路径。

页面、API 和实时日志都需要认证；只有 `/healthz` 无需密码。NAS 本机通常不能直接访问 macvlan 容器，登录请使用另一台设备。

首次操作顺序：

1. 等待启动测速结束，观察「测速进行中」提示和 `SPEEDTEST` 日志。
2. 检查需要的平台是否启用。只使用 Xbox 时保留默认平台即可。
3. 如需更新候选节点，点击「同步 IP」，等待 `SYNC` 日志完成，再点击「全量测速」。
4. 查看平台的当前节点与 IP 池详情。没有有效成绩时显示「上游解析」，属于正常回退。
5. 把 Xbox DNS 指向容器 IP，先保持「302 重写层」关闭，比较真实下载速度。

启动时读取的是本地 IP 列表，不会立即联网同步。自动测速默认开启；如果关掉自动测速，之后重启也不会自动开始测速。

## 2. 状态区和工具按钮

| 项目 | 含义或用法 |
| --- | --- |
| 首选 DNS 地址 | 应设置到 Xbox 的容器地址；核对是否与 `.env` 的 `XBOX_IP` 一致 |
| 监听信息 | 服务启动时实际使用的端口；保存新端口后不会立刻切换 |
| 测速进行中 | 当前有测速任务运行；不要反复点击测速 |
| 需重启提示 | 监听、证书、对外 IP 等配置已保存，重启后才应用 |
| 全量测速 | 对启用、未隐藏、勾选测速且没有锁定 IP 的平台对应池进行完整重排 |
| 同步 IP | 在线更新所有已定义的 IP 池，即使部分平台未启用；不会同步平台域名表 |
| 刷新 | 重新读取当前状态与配置，不触发测速或同步 |

「全量测速」表示检查整个候选池，但下载测速只针对延迟筛选后的前 N 个节点；新鲜度窗口内的有效下载成绩可复用。它并不强制重新下载每个候选的测试文件。

手动触发的任务在后台执行。接口返回成功只表示已提交触发请求，不代表测速或同步已经成功；结果以运行提示、当前节点和日志为准。已有测速时新的完整测速会跳过；同步后增量测速遇到已有测速也会跳过，必要时等空闲后再做一次全量测速。

## 3. 平台开关、测速和隐藏

| 操作 | 影响 |
| --- | --- |
| 平台「启用」 | 对该平台规则中的域名应用 DNS 优选、黑名单和可选换源；关闭后恢复普通解析 |
| 平台「测速」开关 | 是否纳入全量/自动测速；不会自动关闭 DNS 加速 |
| 平台行「测速」按钮 | 手动测试这一 IP 池；只要有该池的启用平台就可使用，不受全局自动测速开关限制 |
| 「详情」 | 展示候选 IP、列表提供的位置、延迟、下载速度，以及池的自动推荐节点 |
| 「隐藏」 | 同时取消启用和参与测速，并从主要平台列表隐藏 |
| 点击已隐藏的平台恢复 | 只恢复显示；需要再手动开启平台和测速开关 |

平台行的「测速」按钮与「测速」开关作用不同。全局自动测速关闭后仍可手动测速；全量手动测速仍按平台的测速开关筛选。锁定 IP 的平台一般不纳入全量/自动测速，但可以通过平台行按钮手动测该池，以便查看自动推荐结果。

`XboxGlobal`、`Ns`、`Ea`、`Battle` 共用 `Akamai` 池。对其中任一平台测速会更新共享池的自动推荐结果；各平台的启用、隐藏和锁定 IP 设置仍独立。

`XboxApp` 的测试 URL 为空，只比较 ICMP/TCP 延迟，不进行下载带宽测量。其默认「测速」开关关闭；没有手动测试或锁定 IP 时会使用上游解析。

### 怎样看测速成绩

- 延迟单位为 `ms`，下载速度单位为 `MiB/s`。`1 MiB = 1,048,576 字节`；`MiB/s × 8.388608 ≈ Mbps`，例如 `10 MiB/s ≈ 83.9 Mbps`。
- `--` 表示未测、未有可展示成绩或延迟失败；下载列「失败」表示已有测量但没有有效下载成绩。
- 延迟最低不一定下载最快。对有下载 URL 的池，只有有效下载成绩参与最终优选。
- 列表中的「位置」来自 IP 文本的标注，不是实时 IP 定位或线路质量保证。
- 本服务的测试资源与实际游戏资源可能不同；最终应比较主机的真实下载。

## 4. 手动锁定与恢复自动 IP

1. 点击目标平台的「锁定 IP」。
2. 填入该平台可用的 IPv4，保存后立即应用。
3. 平台显示「手动锁定」，同时展示该池当前自动推荐地址。
4. 想恢复自动选择，再次点击「锁定 IP」，清空输入并保存。

锁定 IP 会写入 `/data/config.yaml`，重启和升级后保留。它优先于自动测速结果，但不会覆盖已启用的 HTTP/TLS 换源对源域名的 DNS 接管；此时它会用于代理的原域名/目标域名节点选择。

手动 IP 只校验 IPv4 格式，不会在保存时验证游戏资源、证书或下载速度，也没有对失效锁定 IP 的自动切换。请选择该平台实际可用的 CDN 节点。若锁定后异常，清空锁定 IP，再测速或恢复上游解析。

IP 池「详情」标出的冠军是池的自动推荐结果；平台当前使用的节点可能是不同的手动 IP。

## 5. 自动测速、IP 同步与日志设置

### 自动测速

界面支持关闭、每 3/6/12 小时及每天。默认每 6 小时，对应 `0 */6 * * *`，按容器时区的 00:00、06:00、12:00、18:00 触发。

关闭后不会安排周期任务，后续启动和 IP 同步后也不再自动测速。关闭设置不会强行取消已经开始的测速。手动测速按钮仍可使用。

下载样本按节点串行执行，不让本次测量的候选互相抢占出口带宽；Xbox 下载、其他容器和家庭设备仍会影响样本。需要比较线路时，尽量选家庭网络空闲时段。

### 同步列表

界面支持关闭、每天、每 3 天、每周。默认每天 04:00；「每 3 天」使用 cron 日期步进，不等同于始终相隔 72 小时。

关闭只停止周期同步，手动「同步 IP」仍有效。有效新增 IP 在自动测速开启且对应平台符合测速条件时可增量测速；没有新增 IP 时不会借同步重新测完整池。

同步失败或返回 HTML/无效 IP 列表时会保留旧缓存。同步只更新 IP 文本，不会自动合并新的下载域名。

### 记录全部 DNS 查询

默认关闭，日志主要记录加速命中、过滤、屏蔽、换源和任务事件。排查普通域名解析时可以开启，随后观察 `FORWARD` 记录。该开关不是抓包工具，不会记录加密下载正文。

## 6. HTTP 换源与 HTTPS 透传

管理页面当前仍把该区域命名为「302 重写层」，实际开关会同时启停下载 HTTP 和 TLS 两个监听。

### 什么时候尝试开启

已确认纯 DNS 模式正常，但 Xbox 使用国际下载域名时线路较慢，可以尝试开启，并保持「智能兜底」开启。默认规则将指定 `.com` 域名的 HTTP 请求换到对应 `.cn`；并非所有游戏在目标 CDN 上都有可用资源。

操作步骤：

1. 确认平台启用、需要的规则开启、`:80` 和 `:443` 可用。
2. 如果已开启管理 HTTPS 且使用 `:443`，先将管理端口改成 `:8443` 并重启，再开换源。
3. 打开「302 重写层」的「启用」，保留「智能兜底」。
4. 等待客户端 DNS 缓存更新或重新发起下载，观察日志和实际速度。
5. 如效果变差，关闭该开关，等待 DNS 更新后重新下载。

| 请求 | 开启后的处理 | 数据路径 |
| --- | --- | --- |
| HTTP，目标资源存在 | 返回 302，主机请求目标域名 | 后续主机直连目标 CDN |
| HTTP，目标缺失或探测结果未知 | 保留源域名，代理原 CDN | 下载数据经过 NAS |
| HTTPS，SNI 为启用的源域名 | 透传到源域名的原 CDN | 下载数据经过 NAS |

HTTPS 透传不执行 `.com → .cn` 换源，也不解密内容。只有明文 SNI 的 TCP/TLS 请求可路由；没有 QUIC/HTTP3 和加密 SNI 支持。下载透传不使用管理页面的证书。

智能兜底关闭后 HTTP 直接 302，不预先探测资源；可能遇到目标缺失导致下载失败。反向 `.cn → .com` 规则只能在相应正向规则关闭后启用；循环配置会被拒绝，界面会显示错误。

关闭代理或停用源平台时，经代理的连接可能断开。先暂停当前下载，调整后等待解析更新再恢复。服务自答 DNS 的 TTL 为 30 秒，但客户端或其他解析器的缓存行为可能不同。

详细原理见 [下载代理说明](redirect.md)。

## 7. 实时日志如何解读

| 类型 | 代表什么 |
| --- | --- |
| `DNS-A` | 下载域名返回有效的 CDN IPv4 或锁定 IP |
| `DNS-AAAA` | 匹配域名的 IPv6 记录被过滤 |
| `FORWARD` | 部分普通查询转发上游；需要开启记录全部查询 |
| `BLOCK` | 命中启用平台的黑名单，A 返回 `0.0.0.0` |
| `302` | 既可能是 DNS「劫持到本机」，也可能是 HTTP「302 -> 目标」；要看详情文字 |
| `PROXY` | HTTP 回源，包括目标缺失和探测失败，不能只凭该记录断定资源不存在 |
| `SPEEDTEST` | 测速结果或因已有任务而跳过 |
| `SYNC` | 各 IP 文件的同步完成或失败 |
| `SYSTEM` | 服务或配置相关事件 |

仅出现 DNS 接管日志，不代表主机已经执行 HTTP 换源。HTTPS 路径没有资源 URI 日志，因为容器不解密请求；不能用 HTTP 302 日志判断 TLS 透传是否发生。

Web 日志最多保留最近 3000 条，重启后清空，没有内置长期日志库或测速历史曲线。Docker 日志主要用于查看程序启动和致命错误，不能替代 Web 中的 DNS/测速事件流。

## 8. 验证服务与下载效果

### 检查就绪状态

在另一台电脑或手机的浏览器访问：

```text
http://<容器IP>:8080/healthz
```

HTTP 200 和 `ok` 表示 DNS 监听正常，且若开启换源则下载代理监听正常。HTTP 503 表示组件未就绪；该检查不测试上游 DNS、互联网或 CDN 是否可达，也不验证锁定 IP。

### 检查 DNS

在电脑终端使用实际容器 IP，例如：

```bash
nslookup assets1.xboxlive.cn 192.168.1.250
nslookup assets1.xboxlive.com 192.168.1.250
nslookup example.com 192.168.1.250
```

DNS 优选模式下，启用平台的已测速域名应返回其节点。没有有效节点时可能得到正常的上游结果。启用换源时，源域名返回容器 IP 是设计行为；目标域名仍按自身规则解析。

更细的 UDP/TCP/IPv6 检查可在安装了 `dig` 的电脑上执行：

```bash
dig @192.168.1.250 assets1.xboxlive.cn A
dig @192.168.1.250 assets1.xboxlive.cn A +tcp
dig @192.168.1.250 assets1.xboxlive.cn AAAA
```

启用 IPv6 过滤且已有有效 IPv4 节点时，匹配域名的 AAAA 应为空。其他域名不应因此全部丢失 IPv6。

### Xbox 实机验收

1. 选同一游戏、同一网络和接近的时段，记录自动 DNS 下持续数分钟的下载速度。
2. 改用本服务 DNS，等待下载建立后记录持续速度，比较相同单位的数据。
3. 如需换源，单独启用后重复比较，避免同时调整多项设置。
4. 测试暂停/恢复、继续下载、主机正常联网及相关商店功能。
5. 记录模式、所用 IP、时间、出口策略和速度；若有提升再固定配置。

NAS 测速与 Xbox 实际出口不同、家庭带宽正在被占用、CDN 资源分布不同，都可能让测试推荐与真实下载不一致。建议让 NAS 与 Xbox 使用相同的出口和代理/分流策略。

## 9. 常见问题与处理

| 现象 | 优先检查 |
| --- | --- |
| NAS 本机打不开管理页，手机可以 | macvlan 的宿主机隔离；使用另一台设备管理 |
| 所有设备都打不开管理页 | 容器是否启动、容器 IP 是否冲突、网卡 parent/网关/防火墙是否正确 |
| 重复弹出登录框或 401 | 用户名必须为 `admin`；环境变量密码优先于文件；更新密码后重新认证或开新浏览器会话 |
| 页面显示「上游解析」 | 是否完成测速、平台测速是否启用、下载样本是否全部失败；恢复上游属于正常保护 |
| 重启后自动推荐 IP 消失 | 测速成绩不持久化；等启动测速，或在自动测速关闭时手动测速/锁定 IP |
| 修改锁定 IP 后速度为 `--` | 该地址不一定有自动测速记录；锁定只控制使用地址，不自动生成成绩 |
| 「同步 IP」失败 | 在 `SYNC` 日志中看文件和错误，检查出口及下载源；旧缓存仍保留 |
| 换源打开后源域名仍是 CDN IP | 客户端缓存尚未更新、源平台未启用、规则关闭或代理未就绪；从电脑直接查询容器 DNS |
| 换源配置保存失败 | 查看界面错误：端口占用、管理/下载 TLS 冲突、非法 IPv4、重复源域名或循环规则 |
| 停用平台后仍使用旧 IP | 客户端有缓存或既有下载连接；等待、暂停后恢复，必要时恢复自动 DNS |
| 没有 DNS 日志但主机在下载 | 主机可能缓存了 IP，或使用了其他 DNS/代理解析；检查备用 DNS 和路由器策略 |
| health 为 healthy 但下载失败 | 就绪不检查 CDN；检查锁定 IP、上游、IPv6、出口和真实游戏资源 |
| Docker 为 unhealthy 但没有自动重启 | 健康状态只标记异常；普通 `restart: unless-stopped` 不按 unhealthy 触发重启 |
| 网页提示需重启 | 按部署指南重启容器；直接编辑 YAML 时也需要重启 |

Docker 层排查命令，在 NAS SSH 中执行：

```bash
sudo docker ps -a --filter name=xbox-speedup
sudo docker logs --tail 100 xbox-speedup
sudo docker inspect --format '{{.State.Health.Status}}' xbox-speedup
sudo docker network inspect xbox_macvlan
```

## 10. 修改高级配置、密码与停止使用

页面没有完整 YAML 编辑器。上游 DNS、监听地址、下载采样参数、新规则和自定义 cron 等高级设置，可编辑数据目录的 `config.yaml`，或使用 [配置 API](configuration.md)。

直接编辑 YAML 时先停止服务并备份文件，避免被同时进行的页面保存覆盖；编辑完成再启动。通过 Web/API 修改的可热应用项无需重启；Web/API 保存启动参数会显示重启提示。

密码处理：

- 使用环境变量时，在 `.env` 修改 `XBOX_WEB_TOKEN` 后重新创建容器；普通 `docker restart` 不会重新读取 `.env`。
- 使用自动文件密码时，在环境变量保持为空的情况下替换 `web-token` 文件中的密码，再重启服务；保留文件权限。
- 配置 API 不会返回管理密码。数据备份中可能包含密码文件，应按自己的管理凭据保存。

重建、更新、备份及回退的具体命令见 [维护说明](container-image.md)。

停止使用时先把 Xbox DNS 改回自动获取；之后可以停止容器。不要在主机仍依赖它解析时先停掉 DNS 服务。
